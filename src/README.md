# 原型工程结构

- `styles/app.css`：历史整合样式；新增或调整样式不得写入此文件，需迁移到对应模块后删除旧定义。
- `styles/components/`：跨页面复用组件的唯一视觉归属，每个组件单独一个样式文件。
- `styles/modules/home.css`：首页布局、首页组件及首页滚动态样式的唯一归属文件。
- `styles/modules/states.css`：生活服务、商城等页面状态样式；不得重复定义首页专属规则。
- `scripts/components/`：可复用组件的模板、挂载与卸载生命周期；组件不得在 `index.html` 中常驻占位。
- `scripts/app.js`：页面路由和页面内交互；不得承载组件模板或组件样式逻辑。
- `data/`：后续承载商品、分类和入口数据。
- `../backup/index-2026-07-28.html`：拆分前可运行快照。

下一阶段再按页面拆分 CSS 和组件，避免一次性重构造成回归。

## 样式维护准则

- 同一职责只保留一个权威样式定义，按页面或组件归属到对应模块。
- 新样式验证通过后，必须删除被替代的历史样式，不使用不断追加的末尾覆盖来修复问题。
- 修改前先审计同一选择器的全部定义和加载顺序；修改后检查重复选择器、级联冲突、布局偏移和交互回归。
- 页面结构、定位基准、滚动容器和层级关系优先通过明确的布局关系解决，不使用临时偏移、重复 `z-index` 或伪元素遮挡来掩盖问题。
- 新组件必须同时具备独立模板/生命周期文件与独立样式文件；页面模块只能表达页面级布局，不得覆盖组件的基础视觉定义。
